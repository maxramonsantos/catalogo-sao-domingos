===============================================================================
 CATALOGOSD - Guia Comercial de Sao Domingos do Maranhao
 Documentacao da organizacao do projeto e da arquitetura
===============================================================================

Este arquivo explica, em portugues simples, como o projeto esta organizado:
o que cada pasta e arquivo faz, como as pecas se conectam e por que as
escolhas tecnicas foram feitas. Sirva-se dele como mapa sempre que precisar
mexer em algo e nao lembrar onde fica.


-------------------------------------------------------------------------------
1. STACK TECNOLOGICA
-------------------------------------------------------------------------------

- Linguagem/Framework: PHP 8.4 + Laravel 13
  (o pedido original era Laravel 11, mas essa versao ja tinha atingido o fim
  do suporte de seguranca em fev/2026; usamos a versao atual com suporte).

- Interatividade sem recarregar a pagina: Livewire 4
  (usa o novo formato de "Componente de Arquivo Unico", explicado na secao 4).

- JavaScript leve para pequenas interacoes (menu mobile, transicoes): Alpine.js
  (ja vem embutido dentro do Livewire, nao precisa instalar separado).

- Estilizacao: Tailwind CSS 4 (modelo "CSS-first", sem tailwind.config.js;
  a configuracao fica dentro do proprio resources/css/app.css).

- Banco de dados local: SQLite (arquivo unico em database/database.sqlite).
  Em producao pode-se trocar para MySQL so mudando o .env, sem mudar codigo,
  pois o Eloquent (camada de banco do Laravel) abstrai isso.

- Build de assets (CSS/JS): Vite.

- Ambiente local: Laravel Herd (gerencia o PHP, o Composer e o dominio
  http://catalogo-sao-domingos.test).


-------------------------------------------------------------------------------
2. ARQUITETURA GERAL (visao de voo de passaro)
-------------------------------------------------------------------------------

O projeto segue o padrao MVC (Model-View-Controller) do Laravel, mas em vez
de Controllers tradicionais para as paginas interativas, usamos componentes
Livewire, que fazem o papel de "Controller + View reativa" ao mesmo tempo.

Fluxo de uma requisicao para a pagina Inicial ("/"):

  Navegador
     |
     v
  routes/web.php            -> diz que a URL "/" pertence ao componente
                                Livewire "home"
     |
     v
  resources/views/components/⚡home.blade.php
                                 -> classe PHP (sem arquivo separado) com a
                                    logica: busca, filtros e paginacao
                                 -> HTML/Blade com Tailwind logo abaixo da
                                    classe, no mesmo arquivo
     |
     v
  app/Models/Comercio.php (+ Categoria.php + Bairro.php)
                                 -> consultam o banco de dados (SQLite) via
                                    Eloquent (o ORM do Laravel)
     |
     v
  resources/views/layouts/app.blade.php
                                 -> "moldura" com cabecalho, rodape e o
                                    <head> da pagina, que envolve o conteudo
                                    do componente Livewire
     |
     v
  resources/views/components/partials/comercio-card.blade.php
                                 -> pedaco de HTML reutilizavel para desenhar
                                    cada card de comercio na tela

Quando o usuario digita na busca ou clica num filtro, o Livewire manda so os
dados que mudaram para o servidor (via AJAX), roda a logica em PHP de novo e
atualiza apenas o pedaco de HTML necessario na tela -- sem recarregar a
pagina inteira e sem escrever JavaScript customizado.

4. O QUE E UM "COMPONENTE LIVEWIRE DE ARQUIVO UNICO" (SFC)?
-------------------------------------------------------------------------------

No Livewire 3, cada tela interativa exigia 2 arquivos: uma classe PHP (em
app/Livewire/Home.php) e uma view Blade separada (resources/views/livewire/
home.blade.php).

No Livewire 4 (versao usada aqui), existe o formato "Single File Component":
um UNICO arquivo, com o simbolo de raio (⚡) no nome, dentro de
resources/views/components/. O arquivo comeca com um bloco <?php ... ?>
contendo uma classe anonima que estende Livewire\Component, e logo abaixo
vem o HTML/Blade normal daquela tela. E exatamente o que temos em
resources/views/components/⚡home.blade.php.

Vantagem: tudo relacionado aquela tela (dados, logica e visual) fica junto,
mais facil de achar e de dar manutencao em telas pequenas/medias.

5. IDENTIDADE VISUAL
-------------------------------------------------------------------------------

A paleta de cores segue a identidade da cidade:
  - Amarelo/Ambar  -> Abacaxi (cartao-postal de Sao Domingos do Maranhao)
  - Verde Esmeralda -> coroa do abacaxi / vegetacao
  - Azul Sereno     -> Lagoa do Ze Feio

O Hero (topo da pagina inicial) usa um degrade dessas 3 cores com ondas em
SVG simulando a lagoa, ja que ainda nao ha uma foto real aprovada para usar
como fundo. Para trocar por uma foto de verdade no futuro, basta salvar a
imagem em public/images/ e ajustar o bloco <section> do Hero em
resources/views/components/⚡home.blade.php.

6. COMO RODAR E TESTAR LOCALMENTE
-------------------------------------------------------------------------------

1. Site ja fica disponivel em: http://catalogo-sao-domingos.test
   (o Laravel Herd cuida do PHP e do dominio automaticamente).

2. Para desenvolver com atualizacao automatica do CSS/JS, rode em um
   terminal separado e deixe aberto:
       npm run dev

3. Para gerar a versao "de producao" dos assets (usada quando o `npm run
   dev` nao esta rodando):
       npm run build

4. Comandos uteis do Laravel (sempre dentro da pasta do projeto):
       php artisan migrate              -> aplica migrations pendentes
       php artisan db:seed --class=CatalogoSeeder
                                         -> repopula categorias/bairros/
                                            comercios de exemplo
       php artisan route:list           -> lista todas as rotas
       php artisan tinker               -> console interativo para testar
                                            Models/queries
